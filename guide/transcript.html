Walkthrough transcript

Version 0.4.0 · Fictional example · Computer-generated narration.

1. Open and save safely Watch this chapter

Welcome to RAMS Workbench. This guided example uses fictional station data and a computer-generated voice.

Open the browser workbench and wait for the analysis engine. Applied changes are saved on this device, under this site's address.

Check the saving banner. If it says tab only, download a workspace backup before closing. An open editor is still a draft until you save it.

2. Start with the station example Watch this chapter

Choose Explore the station example to create an editable demonstration study. For your own work, choose New project from the Project menu.

The study workspace brings hazards, actions and retained analyses together. Choose a hazard row to continue its review, or a retained analysis to inspect its exact basis.

These counts describe recorded work. They are not a completeness or acceptance score.

3. Define the study Watch this chapter

In Study definition, record the system boundary, configuration, operating context, governing references and acceptance process.

Define operating modes consistently. If you use a risk matrix, enter its source and classes, update the matrix grid, fill the applicable categories, and save the setup.

Missing criteria remain unassessed. The example's invented risk categories are not railway acceptance defaults.

4. Model equipment and functions Watch this chapter

Open System and functions for equipment, functions, interfaces and operating modes. Add each physical instance with a distinct stable ID.

Inspect an equipment item to add children, allocate a function, or open its failure analysis worksheet.

Containment describes the physical system. A reliability success model and a hazard's causal relationships are defined separately.

5. Follow the hazard board Watch this chapter

Select a hazard in Hazard review. Its assessment, boundary and local decision stay above the requirement board.

Each requirement appears once, beside its implementing controls, verification applicability and next action. Select a control to see every requirement row it affects.

Without verification finds missing declarations. A declared pass can still have an open obligation or undefined scope, so read the applicability as well as the result.

6. Add a verification declaration Watch this chapter

Choose Add verification on the relevant requirement. The editor retains the relationship and prefills the available mode, configuration, obligation and requirement revision.

Enter a title, artifact details, applicability and reviewer declaration. An unexecuted plan stays not run. Define the requirement's explicit obligations before claiming coverage.

Save the record, inspect the saved declaration, then return to the board. Saving a plan does not satisfy its obligation or accept the hazard.

7. Record HAZOP examinations Watch this chapter

In the HAZOP worksheet, create a study node with its intent and operating context. Add an examination, select its study node, and record the parameter and guide word.

Describe causes, consequences, safeguards and recommendations. Choose a finding, no issue, deferred, or not applicable disposition, with an appropriate rationale.

Follow a finding into a linked hazard or action. A blank examination is not a completed no-issue review.

8. Develop failure analysis Watch this chapter

The failure modes worksheet can be opened directly or from an equipment record. Select the equipment and add a failure mode.

Keep function and causes, local effects, next-level effects, end effects, detection and compensating provisions distinct.

Select the row to edit, link an existing hazard, create a linked hazard, or assign follow-up work. Criticality notes record your assessment; they do not calculate a risk-priority number.

9. Allocate bow-tie controls Watch this chapter

In Bow tie, select a hazard and inspect its causes, consequences and control allocations. Reuse an existing control when it is the same engineered provision.

Allocate preventive barriers before the hazard and mitigative barriers after it. Controls awaiting path allocation remain visible below the drawing.

Select a node to inspect its record. Use the zoom controls, vector download or Source JSON as needed. Placement does not establish barrier effectiveness or independence.

10. Check and retain a fault-tree result Watch this chapter

Build a static fault tree with AND and OR gates. Reuse a basic-event ID when the same event occurs in more than one branch.

Set the mode and mission horizon. Quantitative analysis needs event probabilities and an independence basis. Check inputs validates without saving a run; Analyze and retain run freezes the result.

The example gives zero point zero four four. Its overlapping cut sets must not be added as mutually exclusive probabilities. Dynamic and dependent models need other methods.

11. Prepare and calculate RAM Watch this chapter

In RAM, define success, mode, mission hours and the repair target. Build series or active-parallel groups using distinct physical instances.

Resolve the component-input checklist. Rates, active repair times, mode, source, conditions and dependency review are required. Check inputs refuses an invalid basis and keeps the draft editable.

Calculate and retain run validates again. Read mission reliability, inherent availability and component repair-time probability as separate quantities.

Retained runs keep their original snapshots. Use importance and sensitivity on a supported run to inspect conditional model drivers. Unsupported standby, shared repair or operational availability are not inferred.

12. Assign and complete actions Watch this chapter

The action register keeps owners, due dates, status and engineering links together. Use its filters to find overdue, unassigned or completed work.

Choose Record completion and retain completion evidence or a controlled reference. This is a separate record from verification coverage and hazard acceptance.

Use Review and trace to inspect technical findings, relationships and change effects. Follow a finding to the record that needs attention.

13. Recover a competing draft Watch this chapter

If another tab saves first, a stale write is refused and your draft stays open. Choose Compare latest revision.

Review both values for each conflicting field, choose the value to keep, then save the combined record. Changes to different fields can be combined.

Download my draft provides a separate copy before leaving the editor. After an interruption, check the saved outcome before repeating a write.

14. Review and freeze a baseline Watch this chapter

Technical review checks recorded content and relationships. An empty findings list does not establish engineering adequacy or complete hazard identification.

Traceability and change review help you follow the affected records. Local hazard decisions still need their own authority, date, rationale and evidence declaration.

In Baselines and history, freeze a named revision and compare it with working content. A frozen snapshot preserves the study; it does not approve it.

15. Share the right output Watch this chapter

Use Download study for a portable read-only review. Download full archive adds project JSON, registers, history, baselines, runs and drawings.

Import project previews JSON and creates a new study identity. It does not reconstruct the whole database history.

Back up workspace preserves all studies and their history. Keep that recovery file outside site storage, especially before changing devices or clearing browser data.

16. Restore and continue independently Watch this chapter

Restore workspace backup inspects a recovery file and shows its study and record counts before replacement. Confirm only after checking that preview.

Download previous workspace recovers the immediately preceding workspace. Keep independent backups for older versions.

The User guide contains the full procedures, feature map, local-app instructions and method boundaries. Use it alongside the workbench as you develop and review your own study.
